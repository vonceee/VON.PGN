Layout Architecture

The application layout in vonchess is built to support both standard responsive web content and full-screen immersive workspaces (like chess analysis boards and drills).

Main Layout Shell

The top-level shell of the application is managed by MainLayoutComponent. Its structure divides the viewport vertically:

  • Sticky Header: Houses primary navigation dropdowns and search bars, with a fixed height and z-index.
  • Main Content Container: Fills remaining vertical space with scroll isolation (flex-1 overflow-y-auto).
  • Conditional Footer: Stays at the bottom of the content container unless hidden dynamically. 
        
<div class="h-screen w-full flex flex-col">
  <app-header class="w-full shrink-0 z-50"></app-header>
  <main class="flex-1 overflow-y-auto w-full relative">
    <div class="flex flex-col min-h-full bg-gradient-to-br from-white via-slate-50/20 to-slate-50/50">
      <div class="w-full flex-1 mx-auto relative">
        <router-outlet></router-outlet>
      </div>
      <app-footer *ngIf="showFooter()" class="w-full shrink-0"></app-footer>
    </div>
  </main>
</div>

Dynamic Footer Visibility

The footer is displayed only on the homepage to keep other workspace and content interfaces clean and distraction-free. This is handled by subscribing to router navigation events: 

        
// main-layout.ts
this.router.events.pipe(
  filter((event): event is NavigationEnd => event instanceof NavigationEnd)
).subscribe((event) => {{ '{' }}
  const url = event.urlAfterRedirects.split('?')[0].split('#')[0];
  const isHome = url === '/' || url === '/home';
  this.showFooter.set(isHome);
{{ '}' }});

Fluid Layout System

For complex multi-column boards, LayoutService offers fluid layouts via an Angular signal. Workspace components toggle the fluid layout programmatically during lifecycle hooks: 

        
// layout.service.ts
@Injectable({{ '{' }} providedIn: 'root' {{ '}' }})
export class LayoutService {{ '{' }}
  isFluid = signal(false);

  setFluid(fluid: boolean) {{ '{' }}
    this.isFluid.set(fluid);
  {{ '}' }}
{{ '}' }}

Tactics & Chessboard Responsive Layout

The workspace layout for puzzles and woodpecker training screens is optimized for both strict viewport alignment on desktop/laptop viewports and fluid scrollable stacking on mobile devices.

1. Layout Grid & Vertical Stretching

To prevent height calculation loops that cause the chessboard to overflow or coordinates to be clipped at the top and bottom, the main grid uses items-stretch (implicit default) on desktop viewports. The left board column is set to 1fr to take up all remaining width, and the entire grid is restricted to max-w-[1080px] mx-auto to center the workspace horizontally on large screens:

2. Parent-Dimension Sizing Calculation

Rather than estimating the available workspace height using viewport math, ChessBoardComponent measures its parent element's actual dimensions directly from the DOM, and fallbacks are used as a fallback if the layout hasn't settled: 

        
// chess-board.component.ts
const parent = this.el.nativeElement.parentElement;
const currentParentHeight = parent ? parent.clientHeight : 0;
const currentParentWidth = parent ? parent.clientWidth : 0;

// Sizing limit constraints
const maxHeight = currentParentHeight || this.containerSize.height || (window.innerHeight - 120);
const maxWidthConstraint = currentParentWidth || maxWidth;

const maxPossible = Math.max(this.minSize, Math.min(maxWidthConstraint, maxHeight));

3. Manual Sizing State

By keeping manualSize set to null during automatic size updates, the chessboard is free to shrink and grow dynamically on window resize events, and is only locked if the user drags the manual resize handle.
